# Исправление ошибки 500 на /todos

## Проблема

Метод `GET /todos` возвращает ошибку 500. Скорее всего это связано с тем, что миграции для полей `priority` и `task_time` не были применены к базе данных.

## Решение

### ⚡ Быстрое решение (рекомендуется)

Самый простой способ - синхронизировать схему с базой данных:

**Windows (PowerShell):**
```powershell
.\apply-migrations.ps1
```

Или вручную:
```powershell
npx prisma db push
```

**Linux/Mac:**
```bash
chmod +x apply-migrations.sh
./apply-migrations.sh
```

Или вручную:
```bash
npx prisma db push
```

### Вариант 1: Применить миграции (для продакшена)

```bash
# Применить все миграции
npm run prisma:migrate
```

Или если миграции уже существуют, но не применены:

```bash
npx prisma migrate deploy
```

### Вариант 2: Синхронизировать схему без миграций

Если вы хотите просто синхронизировать схему Prisma с базой данных:

```bash
npx prisma db push
```

⚠️ **Внимание:** `db push` не создает миграции, только синхронизирует схему. Для продакшена используйте миграции.

### Вариант 3: Проверить статус миграций

```bash
npx prisma migrate status
```

Это покажет, какие миграции применены, а какие нет.

## Проверка

После применения миграций:

1. Перезапустите сервер:
   ```bash
   npm run dev
   ```

2. Проверьте эндпоинт:
   ```bash
   curl http://localhost:3000/todos
   ```
   (с заголовком Authorization: Bearer <token>)

3. Или через Swagger: `http://localhost:3000/api-docs`

## Дополнительная диагностика

Если ошибка сохраняется, проверьте:

1. **Логи сервера** - там должна быть детальная информация об ошибке
2. **Подключение к базе данных** - убедитесь, что база запущена:
   ```bash
   docker-compose ps
   ```
3. **Схема базы данных** - проверьте, что поля существуют:
   ```bash
   npm run prisma:studio
   ```

## Типичные ошибки

### "column does not exist"
- **Причина:** Миграции не применены
- **Решение:** Выполните `npm run prisma:migrate` или `npx prisma db push`

### "Can't reach database server"
- **Причина:** База данных не запущена
- **Решение:** `docker-compose up -d db`

### "Database schema is out of sync"
- **Причина:** Схема Prisma не соответствует базе данных
- **Решение:** `npx prisma db push` или создайте новую миграцию
